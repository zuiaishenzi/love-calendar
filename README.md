# 朝夕 · 恋爱万年历

当前版本：**v1.6.1**。版本记录见 [CHANGELOG.md](CHANGELOG.md)。Node.js 24 + SQLite，使用 Nodemailer 发送邮件、lunar-javascript 计算农历和节气。

## 个人设置、安全设置与岁月拾忆

右上角头像菜单提供个人设置与安全设置。个人设置可选五组系统情侣头像（十张独立选择）或上传自己的 JPG / PNG / WebP 头像（最多5MB），查看用户名、邮箱及账本信息。用户名保持不变；更换邮箱、重置密码在安全设置中完成。

安全设置中的「岁月拾忆」下载含内嵌照片的独立 HTML 纪念册，按日期和首次记录顺序保留双方视角；无需联网即可打开，也可用浏览器打印为 PDF。导出文件包含私密内容，妥善保管。

### 注销与30天保留期

- **注销账号**：账本仅有本人时可用，需绑定邮箱验证码确认。确认后退出登录。30天内原密码登录，或使用原用户名和原邮箱完成注册验证，可恢复原账号、原账本；验证恢复时会设置新密码，不创建新账本。仅输入账号或邮箱、密码错误或验证码错误不会恢复。
- **注销账本**：需账本双方各自在自己的账号中获取验证码并提交确认。以第一份请求创建时刻起计算共同十分钟窗口，双方全部通过后进入30天保留期，重发不延长该窗口；超时必须重新确认。
- **保留期内**：双方可以登录查看或下载故事，但不能修改回忆、提醒、头像或邮箱；提醒邮件暂停。登录不会自动取消双方账本注销。
- **取消账本注销**：双方在同一个十分钟窗口内分别获取和提交取消验证码，全部验证通过后恢复编辑。
- 邮件正文及主题分别为 `注销确认验证码：XXXXXX` 或 `账本取消注销验证码：XXXXXX`。常规注册、绑定和重置密码验证码保持纯数字。
- **到期清理**：服务每分钟检查，启动及处理请求前也会检查；删除运行数据库中的账本、账号、会话、回忆、双方视角、图片、缩略图、头像、提醒、投递记录及相关验证码。停机期间无法执行清理，恢复服务时先清理再接受访问。
- 按部署者确认，**历史备份由部署者管理，不由注销流程自动删除**；用户已下载的纪念册也不受服务控制。恢复旧备份可能恢复已注销的数据，需由部署者再次核对。

旧库自动进行增量表结构升级，不更换密钥，不丢弃既有回忆。上传完整项目后使用原部署更新命令即可。Linux Docker 构建需在服务器验证。

## 数据库加密

V1.5.0 默认整库加密，旧数据库首次启动自动迁移。请保管 `data/.database-key`，已有历史明文备份不会自动转换。升级、密钥与恢复说明见 [数据库加密文档](docs/database-encryption.md)。

## 注册与账本

在注册页填写账号、至少8位密码、邮箱、邮箱验证码及账本号。第一人可点击「生成新号」，第二人填写相同账本号加入。账本号不区分大小写，自动生成10位，手动填写支持8至64位字母、数字或短横线组成。它也是加入凭证，应只告诉另一人。

每本日历最多两个账号，数据库用两个固定席位保证上限；每个账号、邮箱只绑定一本日历，不能换绑。不同账本的回忆、照片、提醒都经过服务端权限隔离。账号/邮箱限制无法识别现实中的同一个人是否另用其他邮箱注册。

## QQ 邮箱配置

1. 在服务器使用的 QQ 邮箱设置中启用 SMTP，获取授权码。授权码不是 QQ 登录密码。
2. 复制 `.env.example` 为 `.env`，填写：

```env
QQ_SMTP_USER=你的发件邮箱@qq.com
QQ_SMTP_AUTH_CODE=该邮箱的SMTP授权码
PORT=3000
APP_ORIGIN=http://localhost:3000
COOKIE_SECURE=false
```

3. 服务固定使用 `smtp.qq.com:465`，通过 TLS 连接。不要将授权码提交到仓库或填进普通用户的个人设置。
4. 验证码邮件主题和正文都只有六位数字，无称呼、签名、链接或模板。邮箱服务商自身附加的传输头/提示不由本应用控制。验证码10分钟有效、单次最多5次验证失败、成功后失效；同一邮箱60秒内不能重发，并设每小时限制。
5. 点击页面右上角「用户名 · 设置」，可绑定/更换自己的收件邮箱或关闭邮件提醒。绑定/更换需要当前密码和新邮箱验证码。

未配置 QQ 邮箱时已有账号仍可登录、记录回忆和设置提醒，但不会发送邮件，也不能完成新用户邮箱注册。收件邮箱不限定 QQ。

邮件连接参考：[Nodemailer SMTP](https://nodemailer.com/smtp)、[腾讯邮件连接参数](https://main.qcloudimg.com/raw/document/product/pdf/1270_46586_cn.pdf)。

## 日历与回忆录

日历从2000年开始，输入年份、选择月份后点击「跳转」或按回车即可切换，支持图文回忆和纵向回忆录。主日历显示农历、二十四节气及节日，选中日期可查看完整名称。内置中国大陆放假调休数据由 lunar-javascript 提供；未收录年份明确显示暂无调休安排，不推测未来放假日期。升级依赖并重启可更新内置数据，实际安排以官方通知为准。

历法来源：[lunar-javascript](https://github.com/6tail/lunar-javascript)。

## 年度提醒

选中日期，点击「每年提醒我们」，填写名称并选择阳历或农历。农历自动由所选公历日期换算并显示确认。可以在「管理全部提醒」编辑、暂停、删除或查看个人最近的邮件发送状态。

- 共享提醒发送给本账本中已验证邮箱且开启邮件提醒的成员；每本最多100条提醒。
- 按北京时间当日09:00开始发送，服务每分钟检查一次。当天晚些时候重启会补发当天尚未发送的提醒；跨天停机不会补发往日提醒。
- 阳历2月29日仅闰年触发；农历闰月仅对应闰月触发，没有对应日期（如部分年份的农历三十）则跳过。不会自动改到其他日期。界面查询未来24年内的下次日期。
- 记录每条提醒、每个收件人、每个日期的发送结果，正常成功发送不会重复；失败间隔15分钟重试，当天最多3次。SMTP成功仅代表服务商接受，无法保证收件箱送达；若服务器在SMTP接受后、写入结果前崩溃，恢复后可能重复一次。
- 提醒邮件使用温暖、平和的文字，不包含验证码模板。服务需持续运行，Linux 建议使用下述 Docker 部署。

## 本地运行

安装 Node.js 24，配置 `.env` 后运行：

```sh
npm ci
npm start
```

打开 http://localhost:3000。`APP_ORIGIN` 必须和访问网址完全一致，不带末尾斜杠。不要直接打开 public/index.html。登录页支持通过绑定邮箱验证码重置密码。

## 从 v1.2.0 升级

先停止旧服务并备份数据目录，安装新依赖后启动。程序自动迁移账号与回忆到同一本账本，并在数据目录生成 `before-v1.3-时间戳.sqlite` 备份。旧密码、会话、文字和照片保留；旧用户需要在个人设置验证收件邮箱后才能接收提醒。账本号在个人设置中查看，原有双人账本已满，不能再注册第三人。

新安装无需 USER1/USER2 环境变量。仅在确实需要预设双人账号时可设置旧版的两组用户名/密码；它们只用于空数据库，账号起初没有邮箱。不要把预览数据目录当成正式数据目录。

## Linux 部署

需要跟随 GitHub `main` 自动更新时，使用 [部署与自动更新指南](deploy/README.md)，内含首次部署、systemd每5分钟检查、测试构建、备份和失败回滚。下述是手动部署方式，两种方式选一种。

安装 Docker、Docker Compose 和 Caddy，上传源码。`.env` 中填写上述QQ邮箱配置，并改为：

```env
PORT=3000
APP_ORIGIN=https://love.example.com
COOKIE_SECURE=true
```

执行：

```sh
docker compose up -d --build
```

将 Caddyfile 的域名替换为自己的域名，DNS指向服务器，将配置合并到 `/etc/caddy/Caddyfile` 后运行 `sudo systemctl reload caddy`。开放80/443端口，并允许服务器出站连接QQ的465端口。Caddy提供HTTPS，应用端口只绑定本机。

数据保存在 `calendar-data` 卷。不要执行 `docker compose down -v`，这会删除数据。密码使用scrypt加独立盐哈希；会话令牌随机生成，Cookie为HttpOnly/SameSite，7天过期。照片需要登录访问。

## 备份与恢复

数据库包含账号、回忆、照片、提醒及发送记录，备份应私密保存。停止服务后复制整个数据目录以确保SQLite WAL一致：

```sh
docker compose stop calendar
docker compose cp calendar:/app/data ./backup-data
docker compose start calendar
```

恢复时停止服务，将备份目录内全部文件复制回 `/app/data`，确认文件归属容器内node用户后启动。回滚v1.2.0时必须同时恢复升级前数据库，旧程序不能安全使用v1.3数据库。

## 图片与验证

每条回忆最多6张图，单张最大5MB，一次上传总量最多17MB。支持JPG/PNG/WebP，原图保存（包含原有EXIF）。

`npm test` 使用隔离数据库和内存邮件适配器，验证验证码正文、过期/失败限制、注册与账本容量、跨账本权限、迁移、阳历/农历匹配、发送去重及失败重试，不会发送真实邮件。真实QQ SMTP投递需配置邮箱后验证。

### 双人视角与提醒接收人（v1.4.4）

每条回忆共享日期和标题；双方点击“写下我的视角”，各自保存文字和最多6张照片，以署名对话气泡显示。保存只更新当前账号的视角，旧回忆及照片自动归于原作者；删除整条回忆仍会删除双方内容。

年度提醒可选择“我们两人”或“仅提醒我自己（对方不可见）”。私密提醒仅本人可以查看、编辑和删除，仅发给本人绑定且开启提醒的邮箱。历史版本的公开单人提醒保持原有可见性，可由接收人改为私密提醒。

### 图片加载（v1.4.4）

日历、回忆录与已保存照片预览使用最长边640像素的WebP缩略图，点击后加载原图。旧照片首次查看时生成并保存缩略图，原图不变。图片响应采用私有缓存，每次复用须通过登录与账本权限验证，未变化时返回304。部署需要安装sharp对应平台的可选依赖，Docker构建已配置自动安装。

### 实时编辑提示（v1.4.4）

双方各开一个前台页面时，无人编辑每人24秒、一人编辑每人15秒、双人编辑每人12秒检查一次，合计约5/8/10次每分钟。打开编辑框、关闭编辑框会立即报告状态，保存和删除通过SSE推送给同账本双方，额外操作请求不计入上述定时频率。SSE每15秒发极小的连接保活注释。多开标签页会增加连接和请求。

仅共同回忆参与编辑提示，不推送私密提醒或草稿内容。状态45秒过期（清理最多额外15秒）；后台暂停心跳并保留状态至超时，恢复前台自动同步。收到更新时保留编辑框中的草稿，关闭编辑框后刷新。服务器单进程保存在线状态，重启后客户端自动重连。反向代理需支持SSE流式响应、关闭缓冲；推送暂时不可用时定时检查仍能发现更新。

### 缩短已有账本号（一次性维护）

仓库提供 `deploy/shorten-ledger-codes.sh`，适用于 `/opt/love-calendar` 的 Docker 部署。先将包含此脚本的仓库更新至服务器，进入仓库目录执行：

```bash
sudo bash deploy/shorten-ledger-codes.sh --check
sudo bash deploy/shorten-ledger-codes.sh --apply
```

`--check` 只报告需要转换的数量。`--apply` 与部署更新共用互斥锁，短暂停止服务，用当前服务镜像里的 Node 运行转换，结束后启动原容器。数据库旁自动生成 `calendar.sqlite.before-short-codes-*.sqlite` 完整备份；备份失败不会修改数据。仅转换超过 10 位的账本号，保留账本 ID 和所有关联数据，重复执行不会再次转换。新号在个人设置查看，旧号不再用于加入。不要公开数据库备份。

非 Docker 部署可停止服务后用 Node.js 24 执行 `node scripts/shorten-ledger-codes.mjs --apply /绝对路径/calendar.sqlite`，完成后启动服务。

### 忘记密码与重置密码（v1.4.6）

登录页点击「忘记密码」，或在个人设置点击「重置密码」，通过账号绑定邮箱的6位验证码设置至少8位的新密码。验证码10分钟有效，最多尝试5次，一次使用后失效。验证码邮件仍只有数字。重置后该账号所有设备需重新登录；未绑定邮箱的账号需先在个人设置绑定邮箱。

## 私密备忘与 AI 整理（v1.6.1）

聊天不再逐条显示时间，相邻消息间隔至少5分钟或跨天时居中提示。聊天窗口点击「历史记录」，可组合筛选北京时间起止日期、文字/图片/语音类型及文字关键词；从新到旧分页显示，已撤回的消息不出现在搜索结果中。

日历上方点击「备忘录」，每个账号独立记录对另一人的喜好、习惯和注意事项。对方及其他账本不能读取这些记录；内容存入原有加密数据库，不进入共享回忆、纪念册导出或 SSE 推送。注销到期会一并删除。

打开备忘录先查看已有条目，点击「新增备忘录」打开填写窗口。长段文字可一键交给 AI 提取多个简短要点，分别放入饮食、习惯、雷点、喜好、心愿和其他分类。同一段原文可以生成多个分类下的条目，原文保留，可展开查看和编辑。修改或删除原文后，该原文提取的全部旧要点失效，其他原文的结果保留。AI 结果需自行核对；失败、超时、格式错误或整理期间记录变化不会覆盖原文。

自定义分类由本人手动维护，该分类下的记录不发送给 AI、不改写。编辑记录可以移动分类；删除自定义分类前需先移动或删除其中记录。每个账号最多200条记录（单条20000字）、20个自定义分类；单次 AI 输入最多20000字，整理间隔至少一分钟。

在服务器 `/opt/love-calendar/shared/.env` 中配置：

```env
LLM_BASE_URL=https://你的服务地址/v1
LLM_API_KEY=你的服务密钥
LLM_MODEL=服务支持的模型名称
```

采用兼容 Chat Completions 的接口，程序自动在 BASE_URL 后追加 `/chat/completions`。密钥仅用于服务器请求，不下发给网页。未配置时手动备忘仍可正常使用，AI 按钮不可用。使用 AI 会将待整理原文发送给所配置的服务商，请选择合适的数据处理策略；用户点击前界面会说明此行为。

更新代码后运行原有 `update.sh` 部署。仅修改 `.env` 而 Git 提交没有变化时，更新脚本会跳过部署；可重建现有容器以加载配置：

```bash
cd /opt/love-calendar
sudo env CALENDAR_IMAGE="love-calendar:$(sudo cat /opt/love-calendar/current)" docker compose -p love-calendar -f /opt/love-calendar/compose.yaml up -d --force-recreate --wait
```

新增表为增量迁移，不替换数据库和密钥。备份继续保存完整数据目录（含 `.database-key`）。
## 双人聊天与语音（v1.6.1）

实时语音通话已移除，保留录音、试听和发送语音消息，无需 STUN/TURN。聊天标题显示「在线 / 离开」：对方页面在前台且保持连接时在线，切到后台、关闭或心跳超过45秒时离开，多个窗口中有一个在线即显示在线。录音需要 HTTPS 或 localhost 和浏览器麦克风权限。

日历上方点击「聊天」，同账本双方可发送文字（4000字以内）、图片（JPG/PNG/WebP，单张5MB）和录音语音消息（录音界面最长2分钟，单条5MB）。图片保存为最长边1600像素的WebP，语音支持WebM、Ogg和MP4；可先试听再发送。每个账号每分钟最多30条，每个账本最多10000条消息。聊天默认显示最新50条，点击「查看更早消息」翻页。消息不可修改，支持撤回自己发送的消息。

聊天记录及附件存入原有加密数据库，只允许同账本双方访问，不进入纪念册导出，也不会发送给LLM。SSE推送新动态，打开聊天时每4秒补查。注销保留期可查看消息，不能发送消息；到期删除聊天数据。

聊天标题显示另一位成员的账号昵称，消息旁显示双方头像。电脑右键或手机长按消息，在菜单中点击「多选」选择1至50条消息，再点击「存入今日回忆」，按北京时间当前日期创建一条「今天的对话」回忆。文字、图片和语音按消息顺序保存，附件独立复制（一次最多25MB），不自动转写语音；收藏后可在日历、回忆录及离线纪念册查看。每次收藏新增一条回忆，不覆盖已有内容。注销只读期间不能收藏，到期会一并清理。


AI 整理生成的分类会保存在本账号下，新增和编辑备忘可直接选择这些分类，或选择「待整理」。自定义分类继续手动维护，不发送给 AI。新增记录保留其他记录的整理结果，编辑只使该条记录的整理结果失效。

聊天消息支持电脑右键、手机长按500毫秒打开菜单，也可用键盘 Shift+F10 打开。文字可复制，未撤回消息可多选存入今日回忆，只能撤回自己发送的消息；撤回后清除原聊天文字或附件并同步显示提示，不能再选中收藏。已存入回忆的独立副本保留。
