# 我们的约定

约定放在日历页内，与月历共用主导航入口。双方可以新增、编辑、标记完成、取消完成，或补记和修改实际完成日期。完成标记显示在日历日期格底部，与回忆红点、右上角休假标记分开。

## 操作方式

- 网页：使用日历页「月历 / 我们的约定」按钮。
- 手机 App：在月历顶部下拉打开约定；在约定清单底部上滑返回月历，也可使用切换按钮。月历左右滑动仍用于切换月份。
- Windows App：月历向下滚动进入约定；清单滚动到顶部后向上滚动返回。编辑框、按钮和可继续滚动的清单不会触发切换。

每本日历最多保存300个约定。同账本双方共享记录，其他账本无法读取或修改；账本注销保留期内只读，到期随账本清理。

## 温馨小字与备忘录 AI

温馨小字直接使用现有服务器环境变量 `LLM_BASE_URL`、`LLM_API_KEY`、`LLM_MODEL`，无需新增密钥。接口使用 OpenAI 兼容的 `/chat/completions`。密钥只保留在服务器环境配置中，不写入客户端或公开源码。

新增或修改约定标题、备注后后台生成一句与活动相关的温馨小字；保存约定无需等待生成完成。生成后存入数据库，双方共享；只修改日期、查看或刷新不会重新生成。模型返回重复文案时尝试重新生成一次；失败仍保留约定，可点击重试。未配置 LLM 时隐藏生成入口，记录功能仍可使用。

备忘录整理提示词同时更新：优先使用已有的概括分类，避免细分和重复归类；相关信息合成一个简洁要点，保留否定、条件、例外、时间和程度。例如「这周胃不舒服，暂时不吃辣」不能改成「不吃辣」。既有整理结果不自动重写，新提示词用于之后的 AI 整理。

## 本次手动更新

正式代码在 `E:\codex\love`。本次不递增显示版本、不生成安装包，试用账号、试用数据及完成进度提示卡片不带入正式版。

1. 双击源码目录的 `上传更新到GitHub.bat`，选择「仅上传源码」；也可自行提交并上传完整源码变更。
2. 上传成功后，在服务器执行：

```bash
sudo bash /opt/love-calendar/bin/update.sh
```

若这个提交曾部署失败且脚本拒绝重复部署，再使用 `--retry`。原有数据与 LLM 环境配置继续沿用，新约定表由服务启动时自动建立。服务器更新完成后重新打开页面或退出重进 App；本次功能使用服务器网页，无需重新安装客户端。
